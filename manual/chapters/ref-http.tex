\chapter{HTTP API reference}\label{ch:ref-http}

The engine's server and the standalone proxy speak the same API for clients, and each adds its own routes for the dashboard and the conductor. This chapter lists them, with who may call each.

\section{Who may call what}\index{auth}

The admin password is the admin token in \code{secrets.env}, and by default it is not set: then every route below answers anyone, and only \code{/metrics} keeps the metrics token when one is set (Section~\ref{sec:dash-login}). With a password set, an admin route needs it as a bearer header or a dashboard session (a cookie the token buys), and a request from the machine itself (loopback, no proxy headers) needs none of them for the read-only admin routes, because the watchdog and the measurement tools rely on that (\code{--trust-loopback}\index{trust-loopback@\texttt{-\kern0pt-trust-loopback}}). The OpenAI routes are open on the engine; behind the proxy, from the first user key on, they need a key from any other machine.

\section{Errors}

Errors are OpenAI-shaped: \code{{"error": {"message", "type", "param", "code"}}}. A 400 names the field or the message part it refuses (\code{param}). A refusal after a stream opened (a queue timeout, a prompt too long, the memory gate) ends the stream with an \code{error} object beside \code{finish_reason: "error"} and \code{[DONE]}. The decision routes keep their own error body, \code{{"type": "error", "error": {...}}}, with 503 and \code{Retry-After} while a model loads or the engine is busy.
